# Галерея баннеров — спецификация v1

Согласовано с заказчиком 27.10.2026. Заменяет неоднозначности `readme.md`.

## 1. Область первой версии

Сервис — внутренний инструмент без авторизации. Три раздела:

| Раздел | Что делает |
|---|---|
| Галерея | Каталог картинок (Ordinary и Popup): ссылка, описание, теги, избранное. |
| Блокнот | Текстовые шаблоны из конструктора: тема, сообщение, теги, фильтры. |
| Конструктор | Два поля на баннере — тема и сообщение, с проверкой **масштаба текста**. Только превью, без экспорта файла. |
| Витрина | Схема страниц приложения с баннерами в посадочных местах и числом клиентов. |
| История | Галерея готовых баннеров с наложенным текстом: избранное, удаление, сортировка по дате. |

### Решения по открытым вопросам

- **Конструктор только показывает превью.** Кнопки «скачать»/«сохранить файл» в v1 нет. Рендер возвращает `PIL.Image`, поэтому экспорт позже добавляется одной функцией без переделки модели данных.
- **«Разные масштабы» = масштаб текста**, а не зум баннера. Масштаб задаётся долей высоты баннера (`text_scale`, 2–20%), поэтому одинаково работает для 1080×1080 и для 728×90.
- **Источник картинок — только внешний URL.** Загрузки файлов, S3 и MinIO в v1 нет. В БД хранится строка URL.
- **Авторизации нет**, но `created_by` заложен в `banners` и `previews` — при добавлении логина миграция не потребуется.
- **Теги — точное совпадение.** Регистр нормализуется (`lower(name)`), частичный поиск по тегам не делается.
- **Ссылка на баннер уникальна.** Уникальный индекс `uq_banners_url` в БД и проверка в `create_banner`/`update_banner` — повторная вставка даёт понятное сообщение, а не трейсбек IntegrityError.
- **Сортировка по цвету.** Цвет берётся из центрального квадрата (20 % от меньшей стороны) как средний RGB. В БД хранится `center_color` (hex) и `center_hue` (оттенок 0–360) — по нему и идёт сортировка «по спектру». Серые баннеры (насыщенность < 6 %) оттенка не имеют и уезжают в конец; NULLS LAST.
- **Шрифт единый** для всего приложения: один TTF в `app/assets/fonts/`, без выбора в UI.
- **Два блока вместо одного поля.** «Тема» — жирным в верхней половине баннера, «Сообщение» — обычным в нижней. Оба блока не выходят за свою половину по вертикали и начинаются от одной левой границы.
- **Отступ задаётся в миллиметрах.** По умолчанию 50 мм при ширине баннера 1000 мм (переводится в 5 % ширины; обе величины настраиваются через `BANNER_WIDTH_MM`/`LEFT_MARGIN_MM`).
- **Сообщение всегда мельче темы** на 3 п.п., включая случай, когда тема ужалась автоподбором.
- **Кегль подбирается под длину текста:** заданный масштаб — это максимум; длинный текст ужимается шрифтом, чтобы целиком влезть в две строки и в свою половину баннера.
- **История хранит готовую картинку.** При сохранении макет рендерится в PNG (до 1280 px) и кладётся файлом в `data/history`, в БД остаётся `image_key`. Поэтому история не зависит от доступности исходного CDN и переживает удаление баннера; параметры тоже сохраняются — чтобы вернуться к настройкам в конструкторе.
- **На посадочном месте в комбинации — один баннер.** Ограничение `uq_placements_combination_slot` в БД; `upsert_placement` заменяет прежний баннер, а не добавляет второй.
- **Комбинаций на страницу много.** `combinations` — отдельная сущность: вариант раскладки и число клиентов у него. Одна и та же страница может иметь десятки вариантов; страница витрины показывает все («Показать все варианты») и даёт выбрать любой.

## 3. Модель данных

```sql
banners (
  id           bigserial primary key,
  url          text not null,                          -- unique constraint uq_banners_url
  description  text not null default '',
  center_color text,                                   -- #RRGGBB из центра картинки
  center_hue   numeric(6,2),                           -- оттенок 0–360, null для серых
  created_by   text,                                   -- задел под авторизацию
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now()
);

tags (
  id           bigserial primary key,
  name         text not null,
  created_at   timestamptz not null default now()
);
create unique index tags_name_lower_uniq on tags (lower(name));

banner_tags (
  banner_id    bigint not null references banners(id) on delete cascade,
  tag_id       bigint not null references tags(id) on delete cascade,
  primary key (banner_id, tag_id)
);

previews (                                             -- история
  id           bigserial primary key,
  banner_id    bigint references banners(id) on delete set null,
  theme_text   text not null,                          -- тема, жирная
  message_text text not null,                          -- сообщение
  theme_scale  numeric(5,4) not null,                  -- доля высоты баннера
  message_scale numeric(5,4) not null,
  theme_pos_x  numeric(5,4) not null,                  -- якорь: левый край при align=left
  theme_pos_y  numeric(5,4) not null,                  -- центр блока, доля высоты
  message_pos_x numeric(5,4) not null,
  message_pos_y numeric(5,4) not null,
  max_width    numeric(5,4) not null,                  -- предел переноса, доля ширины
  align        text not null default 'left',
  color        text not null default '#FFFFFF',
  stroke_width numeric(5,4) not null default 0,        -- обводка, доля кегля
  image_key    text,                                   -- имя PNG в data/history
  is_favorite  boolean not null default false,
  created_by   text,
  created_at   timestamptz not null default now()
);

text_templates (                                      -- Блокнот
  id            bigserial primary key,
  title         text not null default '',
  message       text not null default '',
  source_banner_id bigint references banners(id) on delete set null,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

text_template_tags (
  template_id bigint not null references text_templates(id) on delete cascade,
  tag_id      bigint not null references tags(id) on delete cascade,
  primary key (template_id, tag_id)
);

placements (                                           -- баннеры внутри комбинации
  id             bigserial primary key,
  combination_id bigint not null references combinations(id) on delete cascade,
  slot           text not null,                        -- main | deposits | credits | cards | accounts | top | bottom
  banner_id      bigint references banners(id) on delete cascade,
  text           text not null default '',
  updated_at     timestamptz not null default now()
);
create unique index uq_placements_combination_slot on placements (combination_id, slot);

combinations (                                         -- варианты раскладки на страницу
  id            bigserial primary key,
  page          text not null,                         -- home | loyalty | transactions | catalog
  clients_count integer not null default 0,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);
create index previews_created_at_idx on previews (created_at desc);
```

Шрифт в схеме не хранится — он единый и задан в конфиге.
### Два запроса Истории

```sql
-- «последние запущенные шаблоны»
select * from previews order by created_at desc limit :n;

-- «тексты за последний месяц» для быстрой подстановки — темы и сообщения вместе
select txt, count(*) as uses
from (
    select theme_text as txt, created_at from previews where btrim(theme_text) <> ''
    union all
    select message_text, created_at from previews where btrim(message_text) <> ''
) merged
where created_at > now() - interval '1 month'
group by txt
order by uses desc
limit 50;
```

## 4. Рендер

`app/core/render.py` — чистые функции, не зависящие от Streamlit (тестируются напрямую).

```python
@dataclass(frozen=True)
class TextBlock:
    text: str
    text_scale: float      # 0.01 .. 0.20, это МАКСИМУМ для автоподбора
    pos_x: float = 0.05    # якорь: левый край при align=left
    pos_y: float = 0.25    # центр блока в своей половине
    max_width: float = 0.78
    align: str = "left"
    color: str = "#FFFFFF"
    stroke_width: float = 0.0
    weight: str = "Regular"
    zone: str = "upper"    # upper | lower | any

@dataclass(frozen=True)
class BannerSpec:
    theme: TextBlock
    message: TextBlock
```

Правила:

1. Кегль = `round(text_scale * img.height)`, минимум 8 px.
2. Перенос по словам до `max_width * img.width`; слова длиннее строки режутся принудительно.
3. **Не больше двух строк на блок.** Если текст не влезает, кегль уменьшается (бинарный поиск от заданного масштаба вниз). Многоточие — только если не помогло даже 8 px.
4. **Зона:** тема живёт в верхней половине, сообщение — в нижней. Блок центрируется по вертикали внутри своей половины и не может её пересечь; высота блока ограничена 92 % половины.
5. `pos_x` — якорь блока: левый край при `align=left`, центр при `center`, правый при `right`. Один отступ → тема и сообщение на одном уровне.
6. Тема рисуется жирным (`Bold`), сообщение — `Regular`. Вариативный Inter: начертание выставляется через `set_variation_by_name`.
7. После автоподбора кегль сообщения ограничен 85 % от кегля темы — сообщение всегда мельче.
8. Входное изображение не мутируется: работа на копии.

## 5. Загрузка изображений

`app/core/images.py`:

- `requests.get(stream=True)`, таймаут 10 с, лимит 20 МБ, проверка `Content-Type`
- дисковый кэш `data/cache/<sha256(url)>`, TTL 24 ч
- `ImageOps.exif_transpose` → `convert("RGBA")`
- ошибки (404, таймаут, не картинка) → понятное сообщение в UI, кэш не отравляется
- перед рендером превью — ресайз до 560 px по длинной стороне; полный размер только в режиме 1:1

## 6. Экраны

**Галерея**: сайдбар — поиск по описанию (`ILIKE`), мультивыбор тегов (AND), сортировка «по цвету баннера» (по умолчанию) или «сначала новые», кнопка «Пересчитать цвета». Пагинация по 12. Сетка 4 в ряд: кликабельная миниатюра (ведёт в конструктор), чипы тегов и три кнопки-иконки: копировать ссылку, редактировать, удалить (с подтверждением в модальном окне). Новый баннер — кнопкой над сеткой, форма в модальном окне; цвет центра считается при добавлении и редактировании, повторная ссылка отклоняется.

**Конструктор**: выбор баннера; два поля — «Тема» и «Сообщение»; группа «Шрифты» (масштабы 5–20 % и 1–17 %, цвет — по умолчанию чёрный `#000000`, обводка) раскрыта по умолчанию; группа «Выравнивание» (выравнивание, отступ слева 50 мм, вертикальные позиции 0.35/0.65, предел ширины 0.70) — свёрнута. Превью уменьшено и обновляется на каждое изменение. «Сравнить масштабы» показывает три превью подряд — меньше на N, текущий, больше на N — вертикально, без рамки. «1:1» — рендер в натуральную величину. Кнопка «Сохранить в историю».

**Витрина**: фильтр по четырём страницам. Сверху — счётчик вариантов, переключатель «Показать все варианты» и кнопка «Новая комбинация». При включённом переключателе все варианты рисуются миниатюрами в две колонки; под каждой — номер, число клиентов и сколько мест заполнено, плюс кнопка «Открыть этот вариант». Ниже — выбранный вариант: схема экрана в «телефоне», метрики, список мест, форма постановки баннера, поле числа клиентов и кнопки «Дублировать вариант» / «Удалить вариант». Места заданы в `app/core/showcase.py`: Главный — основной баннер, под вкладами/кредитами/картами/счетами; Лояльность — сверху и снизу; История транзакций и Продуктовый каталог — сверху. Картинки самого приложения пока условные (блоки-заглушки), подставятся позже.

**История**: галерея готовых картинок (3 в ряд). Сверху — сортировка по дате (сначала новые / старые) и переключатель «Только избранное» со счётчиком. На карточке: рендер баннера, тема и сообщение, масштабы и дата, две иконки — звезда (избранное) и корзина (удаление с подтверждением в модальном окне), плюс ссылка «Открыть в конструкторе», которая возвращает к баннеру с сохранёнными настройками.

## 7. Производительность

Streamlit перезапускает скрипт на каждое движение виджета, поэтому:

- `@st.cache_data` на скачивание байтов по URL
- `@st.cache_resource` на `ImageFont` (кеш по размеру кегля через `lru_cache`)
- `@st.cache_data` на `render_banner` по хэшу аргументов (url, тексты, параметры)
- бюджет: один рендер 1080×1080 — 20–80 мс с учётом автоподбора кегля

## 11. Риски

- **Внешние URL**: битые ссылки, hotlink-защита, медленные CDN, `http` без TLS. Смягчение — таймауты, кэш, явные сообщения об ошибке.
- **Крупные исходники** (4000×6000) — ресайз перед превью, иначе UI встаёт.
- **Эмодзи и редкие символы** отсутствуют в едином шрифте — появятся «тофу»-квадраты. Предупредить пользователя при вводе.
- **Перерисовка** при каждом ре-ране — закрывается кэшем из п. 7.

## 13. Структура экранов по референсам (AppToBanner)

Макеты витрины повторяют реальные экраны приложения из каталога `AppToBanner/`.

**Главная.** Оранжевый градиентный хедер (аватар «ДВ», поиск, уведомления, «Здравствуйте, Дмитрий Викторович!»). Белая шторка ниже: карточка «В кошельке» с четырьмя плитками-иконками; две плитки «Кэшбэк и бонусы» и «Траты за октябрь». Дальше посадочные места в порядке: **основной баннер**, секция «Карты» → **под картами**, «Вклады и накопления» → **под вкладами**, «Счета» → **под счетами**, «Кредиты» → **под кредитами**, кнопка «Открыть новый продукт».

**Кэшбэк и бонусы (Лояльность).** Синий градиентный хедер с заголовком. Белая карточка «Копится в октябре» с прогрессом и «899 ★ из 5 000 ★»; две карточки «История» и «Детализация»; **баннер сверху**; карточка «CARD ТП Кошелек Gold 7,59 ₽»; блок «Приглашайте друзей» с двумя плитками; **баннер снизу**.

**История операций.** Заголовок «История операций», ряд чипов-фильтров (⚙, Пополнение, Списание, Кэшбэк), белая карточка «Траты за октябрь 335 177,32 ₽», **баннер сверху**, далее список операций с датами («Сегодня», «26 октября, понедельник»).

**Продуктовый каталог.** Заголовок с шевроном «Продуктовый каталог», **баннер сверху**, список белых карточек продуктов (иконка + название + подпись): «Взять кредит», «Рефинансирование», «Выпустить дебетовую карту», «Открыть вклад».

**Как выглядит баннер в приложении.** Скруглённый блок на всю ширину с отступами ~12 px; креатив занимает весь блок; в правом верхнем углу — крестик закрытия. Текст, если он есть в креативе, стоит слева.

**Витрина: два источника.** Переключатель «Источник»: «Комбинации из Airflow» (таблица `communication_showcase`, только чтение) и «Избранное из истории» (снимки из истории с отметкой «Избранное» — по одному баннеру на каждое место страницы, примерка без сохранения).

### Визуальные токены из референсов

- Фон приложения — светло-серый `#F4F5F7`, карточки белые, радиус 16 px, лёгкая тень.
- Акцент — оранжевый `#FF6A13`; хедер главной — градиент `#FFB25C → #FF8A3D → #FF5F00`, хедер «Кэшбэк и бонусы» — синий `#6FB6FF → #2F6FE0`.
- Баннер: блок на всю ширину с отступами 12 px по краям, радиус 16 px, крестик закрытия в правом верхнем углу — белый кружок 18 px.
- Нижняя навигация: «Главная», «История», «Платежи», «Поддержка», «Ещё»; активный пункт оранжевый.
- Шрифт в макете — Inter; заголовки 14–18 px с плотным начертанием, подписи 10–11 px серые.
