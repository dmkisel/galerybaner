# Галерея шаблонов

Внутренний сервис: каталог шаблонов (баннеры, push, СМС), конструктор текста на баннере, витрина коммуникаций и история готовых макетов.

## Возможности

**Галерея шаблонов** — только картинки: Ordinary и Popup. Фильтр по типу,
поиск по описанию, теги (точное совпадение), сортировка по цвету, датам и длине
текста, пагинация. Карточки идут сеткой, картинка кликабельна и ведёт в
конструктор. У каждой карточки есть галочка «Избранное» (пишется в БД) и
переключатель «Только избранное» в сайдбаре. Ссылки на картинки уникальны — повторную
добавить нельзя. Цвет берётся из центрального квадрата картинки и сортируется
по оттенку.

**Блокнот** — все текстовые шаблоны, собранные в конструкторе. Поиск по тексту,
фильтр по тегам, сортировка по датам и длине. В карточке — тема, текст, счётчики
символов и найденные переменные; кнопка открывает шаблон в конструкторе, корзина
удаляет.

**Конструктор** — для баннеров с картинкой. Ordinary: два поля «Тема» (жирным,
верхняя половина) и «Сообщение» (обычным, нижняя), оба от одной левой границы
(50 мм), не длиннее двух строк и 70 % ширины, текст по умолчанию чёрный.
Popup: белая скруглённая подложка, выступающая по краям, картинка со
скруглением, тема, сообщение и насыщенная оранжевая кнопка. Кнопка «Сохранить
в шаблон» кладёт тексты в Блокнот, «Сохранить в историю» — песочница со снимком
макета.

**Витрина** — какие баннеры стоят в посадочных местах приложения. Фильтр по
страницам: Главный (основной баннер, под вкладами, кредитами, картами,
счетами), Лояльность (сверху и снизу), История транзакций и Продуктовый каталог
(сверху). Вариантов на страницу много: каждый — отдельная комбинация со своим
числом клиентов; переключатель «Показать все варианты» рисует все миниатюрами.
Вариант можно создать, скопировать, переименовать по числу клиентов и удалить;
на одно место в комбинации — только один баннер.

**История** — галерея готовых баннеров с уже наложенным текстом. Картинка
рендерится при сохранении и лежит файлом в `data/history` (том Docker), в БД —
только ключ; поэтому запись переживает удаление баннера. Сортировка по дате
(новые / старые), фильтр «только избранное», звёздочка добавляет в избранное,
корзина удаляет запись вместе с файлом.

## Стек

Docker Compose, Streamlit, Postgres 16, Pillow, SQLAlchemy 2.0 + Alembic.

## Быстрый старт

```bash
cp .env.example .env          # при необходимости поправьте порты и пароль
docker compose up -d --build  # db + миграции + приложение
```

Интерфейс: <http://localhost:8501>. Postgres снаружи: `localhost:5433`.

Каталог стартует пустым: первый баннер заводится кнопкой «Добавить баннер»
над сеткой — нужна ссылка на картинку, описание и теги.

## Тесты

```bash
docker compose --profile tools run --rm test
```

Команда разворачивает отдельную базу `galerybaner_test`, прогоняет миграции,
затем `alembic check` (сверка моделей с миграциями — ловит расхождения схемы) и
`pytest`. Тесты репозитория и смоук-тесты страниц пропускаются, если база не
задана: имя базы обязано содержать `test`, чтобы нельзя было случайно очистить
рабочие данные.

Локально без Docker: `pip install -r requirements-dev.txt && pytest` — тесты
рендера и текстовых хелперов работают без базы.

```
app/
├── main.py                входная точка, st.navigation
├── ui/                    страницы Streamlit
│   ├── common.py          кэшированные обёртки над загрузкой и рендером
│   ├── gallery.py         галерея картинок: типы, фильтры, избранное
│   ├── notepad.py         блокнот: текстовые шаблоны, фильтры
│   ├── constructor.py     баннер и popup: тексты, масштабы, сохранение
│   ├── showcase.py        витрина: схема страниц и посадочные места
│   └── history.py         история готовых картинок, избранное
├── core/                  логика без Streamlit — тестируется напрямую
│   ├── config.py          настройки из переменных окружения
│   ├── db.py              движок и транзакции
│   ├── models.py          модели SQLAlchemy
│   ├── repo.py            все запросы к Postgres
│   ├── render.py          рендер текста (Pillow), чистые функции
│   ├── images.py          скачивание по URL, дисковый кэш, миниатюры
│   ├── colors.py          цвет центра баннера для сортировки
│   ├── popup.py           рендер popup: подложка, тема, сообщение, кнопка
│   ├── templates.py       типы шаблонов, переменные, счётчики
│   ├── showcase.py        описание страниц и посадочных мест
│   ├── storage.py         файлы истории (PNG на томе)
│   └── texts.py           нормализация тегов и текстовые хелперы
└── assets/fonts/          Inter (вариативный) + OFL
migrations/                Alembic
tests/                     pytest
```

`app/core` не импортирует Streamlit и не знает про сессии — поэтому рендер,
нормализация тегов и запросы проверяются обычными unit-тестами.

## Ключевые решения

- **Масштаб текста — доля высоты баннера**, а не абсолютный кегль: 15,5 % даёт
  сопоставимый результат на 1080×1080 и на 728×90.
- **Кегль подбирается под длину текста.** Заданный масштаб — это максимум:
  длинный текст ужимается шрифтом, чтобы целиком влезть в две строки и в свою
  половину баннера. Многоточие — только если не помогло даже 8 px.
- **Блоки не пересекают середину.** Тема центрируется в верхней половине,
  сообщение — в нижней; высота блока ограничена 92 % половины. Кегль сообщения
  дополнительно ограничен 85 % от кегля темы — оно всегда мельче.
- **В БД только ссылки.** Картинки не хранятся: они скачиваются по URL и
  кэшируются на диске с TTL (по умолчанию 24 ч), чтобы галерея не зависела от
  доступности чужого CDN и не ходила в сеть на каждый ре-ран Streamlit.
- **Теги — точное совпадение.** Регистр хранится для отображения (`name`), а
  сравнение идёт по нормализованному ключу (`name_key`, уникальный).
- **История хранит готовую картинку.** При сохранении макет рендерится в PNG
  (до 1280 px) и кладётся файлом в `data/history`, в БД остаётся `image_key`;
  поэтому запись переживает удаление баннера и не зависит от чужого CDN.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | собирается из `POSTGRES_*` | строка подключения |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `galerybaner` / `app` / `app` | параметры БД |
| `APP_PORT` / `POSTGRES_HOST_PORT` | `8501` / `5433` | порты на хосте |
| `FONT_PATH` | `app/assets/fonts/Inter-Variable.ttf` | шрифт рендера |
| `CACHE_DIR` / `CACHE_TTL_HOURS` | `data/cache` / `24` | кэш картинок |
| `IMAGES_ALLOW_PRIVATE_HOSTS` | `true` | разрешать ссылки на локальные адреса |
| `GALLERY_PAGE_SIZE` / `GALLERY_COLUMNS` | `12` / `4` | размер страницы каталога |
| `HISTORY_LIMIT` | `24` | сколько превью показывать в истории |
| `RECENT_TEXTS_DAYS` | `30` | окно «текстов за месяц» |
| `PREVIEW_MAX_SIDE` | `1100` | уменьшение превью в конструкторе |

## Ограничения версии

Нет экспорта готового файла, загрузки картинок файлами, авторизации и выбора
шрифта в интерфейсе. В схеме уже есть `created_by` у баннеров и превью — под
будущий вход по логину. Подробности и обоснование — в `docs/spec.md`.

## Диагностика

- **Картинки не отображаются** — контейнеру нужен интернет; часть CDN отдаёт
  картинки только со сторонним Referer. Ошибка видна на карточке.
- **Внутренний CDN на приватном адресе** — оставьте `IMAGES_ALLOW_PRIVATE_HOSTS=true`.
  Если сервис выставляется наружу, поставьте `false`: тогда ссылки на локальные
  адреса будут отклоняться.
- **Шрифт не найден** — рендер откатывается на DejaVu Sans из образа; свой шрифт
  кладётся в `app/assets/fonts/` и указывается в `FONT_PATH`.
